# Hosted flight scoring

The scene uses Decentraland's native Multiplayer Server and Storage, following https://docs.decentraland.org/creator/scenes-sdk7/networking/authoritative-servers. SDK/runtime are pinned to the compatible auth-server release, and both scene manifests enable `authoritativeMultiplayer`.

## Run lifecycle

- Ready: standing or spawning on the ground earns no time. Takeoff requires 150 ms of confirmed unsupported height above the lava/ground surface.
- Airborne: observed server simulation time counts, including hovering without transform displacement. Camera motion never starts a flight.
- Paused: supported on a leaf/rock, unfocused, outside the playable volume, or no recent client focus heartbeat. Returning discards the boundary interval.
- Finished: continuous lava occupancy freezes the completed result exactly once. The displayed result remains until a new confirmed takeoff resets the counter. Disconnection/large gaps/unknown teleports interrupt rather than submit a valid flight.

The lava footprint follows the transformed authored lava mesh bounds. Its contact height includes the arena's physical floor. A rock touch begins a 1.5-second recovery window, refreshed while the player is supported by that rock, but protection applies only while its active collider touches the player. When the collider drops or the player leaves it, blue-lava contact immediately finishes the run. The timer remains paused while grounded and resumes if the player lifts off. Native rays and the old thin floor trigger remain supplemental local feedback; they do not own authoritative completion.

`Airtime` implements the shared state machine. `FlightAuthority` samples server-owned avatar positions and creates completed results. `flight-server.ts` uses authenticated wallet identities from message context and engine identity components. Client messages carry only supported/focused flags and a display name; they carry no wallet address, position, duration or score. Support/focus hints can pause the timer, so this is not a complete server physics simulation of client-local moving leaves. Platform support hints are not a proof against deliberately modified clients.

## Persistence and results

Completed personal bests are held in server memory, saved per wallet under Player Storage key `endless-vortex:personal-best:v2`, and mirrored in scene Storage key `endless-vortex:completed-flights:v2`. A returning wallet loads its personal record before scoring begins. Personal and shared records reconcile to the higher best. Personal writes and the shared checkpoint must both succeed before the save is acknowledged; failed writes remain pending. Reads are checked before enabling scoring; malformed/unavailable storage fails closed and retries. Writes are serialized; failures remain dirty and retry every five seconds. A slower checkpoint cannot overwrite a newer multiplayer result. Clients see saving status until the world checkpoint succeeds. Rankings use completed best duration, shared ranks for ties, deterministic wallet ordering and include the local player's rank below the top ten. Restart/join loads the same records.

Each landing produces a server result ID. Lower/equal results show red text/digits and retain the existing best; new personal bests use blue digits and gold accents. The local run captures its prior best at takeoff, so a fast server update cannot turn its new-record popup red. Local lava contact immediately creates a provisional result event, without waiting for a server packet. If the best has not loaded yet, the pending result uses blue/gold with "CHECKING PERSONAL BEST" and does not claim a saved record. The server reconciles its score and save status without restarting the animation. The center card remains readable for 3.8 seconds even if lift causes immediate takeoff; it also renders above an open Flight Guide. UI score glyphs use the existing image atlas plus a generated red variant to avoid native font digit artifacts. Regenerate digit artwork with `npm run result:assets`. Result-specific beveled frames, smooth screen vignettes (red or blue/gold), and the cyan reset glow come from `npm run flight:assets`. The card eases into view; its vignette settles to a softer edge glow during the result presentation. On a server-confirmed new flight, old digits wipe upward while fresh digits reveal with a gold sweep and a short blue/gold vignette. The 650 ms counter animation stays clipped inside its existing layout and never modifies the numeric score. The event fires once per completed run, including a takeoff immediately followed by a platform pause.

## Verification and operation

Run `npm test` and `npm run build`. Tests cover camera/focus changes on lava, takeoff noise, one-time completion, result palettes/bounds, two-player ranking, storage failures, corrupted reads and save ordering across restarts. The SDK's `npm start` launches local headless multiplayer automatically. If Creator Hub's preview server exits during a scene reload and the HUD stays on "RECORDS LOADING", run `npm run preview:records` in a separate terminal while the port 8000 preview is open. The local helper reconnects after later scene reloads. Preview storage lives under the SDK commands runtime data directory. Publish the scene normally to enable the hosted server in production. Local preview storage and production storage are separate. The legacy HTTP service and its JSON file are not used or migrated by this path.

Native two-player and physical mobile collision feel still require in-client playtesting. No production scene or production Storage is modified by the local tests.

The 15, 30 and 60-second goals queue centered Bronze, Silver and Gold achievement cards, with the earned emblem and image-font goal digits. Each goal fires once per run, including when the next position sample is already paused or finished. Landing results take priority; achievements wait rather than overlap, and later hundred-second awards do not cover them. New takeoff rearms the goals.
